# 🏛️ معماری کلان نرم‌افزار (System Architecture)

این بخش معماری لایه‌ای کلاینت اندرویدی کالینان، الگوهای طراحی انتخاب‌شده و جریان گردش داده‌ها در اپلیکیشن را شرح می‌دهد.

---

## ۱. الگوی معماری MVVM و Clean Architecture

پروژه کالینان بر اساس الگوی رسمی **MVVM (Model-View-ViewModel)** و با الهام از اصول معماری تمیز (Clean Architecture) در سه لایه اصلی سازمان‌دهی شده است:

```
[UI Layer (Screens & Composables)] 
       ▲               │
       │ State         │ Events / User Actions
       │               ▼
[ViewModel Layer (StateFlow & Coroutines)]
       ▲               │
       │ Results       │ Suspend Functions
       │               ▼
[Data Layer (Repositories & Network Client)]
       │
       ▼ (HTTP/HTTPS)
[ASP.NET Web Forms Server (jeton.bums.ac.ir)]
```

### ۱. لایه نمایش (UI Layer)
- **فناوری:** ۱۰۰٪ مبتنی بر **Jetpack Compose** (بدون حتی یک فایل XML Layout قدیمی).
- **جهت‌گیری راست به چپ (RTL):** پشتیبانی کامل از چینش بومی فارسی با کانتینر اختصاصی `PersianRtlLayout` و فونت‌های استاندارد.
- **طراحی ریسپانسیو و واکنش‌گرا:** سازگار با گوشی‌های کامپکت، تبلت‌ها و پنجره‌های چندوظیفگی (Multi-Window).
- **مدیریت وضعیت:** صفحه فقط خواننده و نمایش‌دهنده `StateFlow` است و از ایجاد منطق تجاری داخل کامپوزبل‌ها اجتناب شده است.

### ۲. لایه مدیریت حالت (ViewModel Layer)
- **کلاس‌های کلیدی:**
  - `AuthViewModel`: مدیریت فیلدهای ورودی کاربر، گذرواژه، کد امنیتی کپچا، خطاها، لودینگ و کنترل نشست.
  - `MenuViewModel`: نگهداری برنامه غذایی هفته جاری، هدایت به هفته‌های قبل/بعد، فیلتر وعده‌ها (صبحانه/ناهار/شام) و عملیات رزرو/لغو.
- **جریان یک‌طرفه داده‌ها (Unidirectional Data Flow - UDF):** تمام تغییرات از طریق رویدادهای مشخص مانند `onUsernameChange`، `refreshCaptcha` و `navigateWeek` به ویومدل ارسال شده و وضعیت‌های جدید از طریق `StateFlow` به صورت واکنشی (Reactive) ساطع می‌شوند.

### ۳. لایه داده (Data Layer)
- **مخازن (Repositories):**
  - `AuthRepository`: واکشی صفحه ورود، استخراج توکن‌های ViewState و کلید عمومی RSA، دریافت تصویر باینری کپچا و ارسال درخواست احراز هویت.
  - `MenuRepository`: اجرای درخواست‌های جابه‌جایی هفته، تولید فرم‌بادی وب‌فرم مایکروسافت، ارسال پی‌لود رزرو یا لغو غذا و تفسیر خروجی دلتا.
- **کلاینت شبکه (`CullinanHttpClient`):** کلاینت تک‌نمونه (Singleton) مبتنی بر OkHttp با قابلیت مدیریت خودکار کوکی‌ها و سوئیچ هوشمند به حالت سازگار با گواهی‌های دانشگاهی.
- **تحلیل‌گرها (Parsers):**
  - `ReservationHtmlParser`: استخراج اعتبارات ریالی، روزهای هفته، وضعیت رزرو هر وعده، غذاهای جایگزین و سلف‌ها با کتابخانه قدرتمند Jsoup.
  - `DeltaParser`: پارسر اختصاصی فریم‌های ناهمگام وب‌فرم‌های ASP.NET AJAX (فرمت `length|type|id|content`).

---

## ۲. ایمنی همزمانی (Concurrency & Thread Safety)

- **انزوا در نخ‌های پس‌زمینه (Background Thread Isolation):** تمام عملیات شبکه و پردازش سنگین رشته‌های طولانی HTML با `withContext(Dispatchers.IO)` انجام می‌شود تا Main Thread همواره در فرکانس ۶۰/۱۲۰ هرتز نرم و بدون لگ باقی بماند.
- **همگام‌سازی با Mutex:** در `MenuRepository`، جهت جلوگیری از شرایط رقابتی (Race Conditions) هنگام کلیک سریع روی دکمه‌های رزرو، از `Mutex.withLock` استفاده شده تا درخواست‌های ذخیره و جابه‌جایی هفته به صورت مرتب و مطمئن به سرور ارسال شوند.

---

## ۳. سیستم لاگ‌گیری امن و ناوبری دوگانه (Logging & Settings Navigation)

- **ناوبری دوگانه تب‌ها (Bottom Navigation Bar):** پس از ورود کاربر، نوار ناوبری پایین صفحه دسترسی به دو تب «رزرو غذا» و «تنظیمات» را فراهم می‌کند.
- **موتور لاگ‌گیری امن چرخشی (`AppLogger`):** ثبت تمامی رویدادها، متدهای HTTP و رفتارهای خزش وب با فیلتر خودکار فیلدهای محرمانه (گذرواژه و کوکی‌های سشن) و بافر چرخشی با سقف ۳ مگابایت.
- **حالت مخفی توسعه‌دهنده (Easter Egg):** دسترسی به ابزارهای عیب‌یابی، مشاهده رویدادها و استخراج لاگ‌ها تنها با ۷ بار کلیک روی شماره نسخه در صفحه تنظیمات فعال می‌شود.
