# 🛠️ پشته فناوری و وابستگی‌ها (Tech Stack & Dependencies)

این سند کتابخانه‌ها، ابزارها و چارچوب‌های استفاده‌شده در پروژه کالینان را به همراه علت انتخاب هر یک تشریح می‌کند.

---

## ۱. جدول فناوری‌های هسته

| دسته‌بندی | ابزار / کتابخانه | نسخه / استاندارد | علت و مزیت انتخاب |
|---|---|:---:|---|
| **زبان برنامه‌نویسی** | **Kotlin** | `2.0+` | ایمنی در برابر Null، کدهای بهینه، Coroutines و توسعه سریع مدرن اندروید |
| **رابط کاربری (UI)** | **Jetpack Compose** | `BOM 2024+` | سیستم UI مدرن و اعلانی (Declarative) اندروید، بدون XML و با حداکثر بهره‌وری |
| **سیستم طراحی** | **Material Design 3 (M3)** | آخرین نگارش M3 | طراحی مدرن با پالت‌های رنگی جذاب، گوشه‌های گرد، کارت‌ها و انیمیشن‌های روان |
| **ارتباطات شبکه** | **OkHttp 3** | `4.12+` | سریع‌ترین و پایدارترین کلاینت HTTP/HTTPS در اکوسیستم جاوا و اندروید با پشتیبانی از Connection Pooling و HTTP/2 |
| **مدیریت کوکی‌ها** | **CullinanCookieJar** | سفارشی | حفظ نشست کاربری `ASP.NET_SessionId` در حافظه و اشتراک آن بین لایه‌های احراز هویت و رزرواسیون |
| **تجزیه HTML** | **Jsoup** | `1.18+` | ابزار استاندارد و سریع برای تحلیل DOM، استخراج فیلدهای مخفی ASP.NET و سلکتورهای CSS |
| **مدیریت وضعیت** | **ViewModel & StateFlow** | AndroidX Lifecycle | جریان‌های واکنشی با معماری UDF و ایمنی در چرخه حیات اکتیویتی |
| **تست‌های واحد** | **JUnit 4 & MockWebServer** | تست‌های محلی JVM | تست رفتار کلاینت شبکه، شبیه‌سازی کدهای وضعیت HTTP و تست‌های دقیق بدون نیاز به امولاتور یا اینترنت |

## ۲. ساختار کاتالوگ وابستگی‌ها (`gradle/libs.versions.toml`)

تمام نسخه‌های وابستگی‌ها در فایل متمرکز کاتالوگ نسخه (`libs.versions.toml`) مدیریت می‌شوند:
- تغییر نسخه‌ها فقط در یک نقطه انجام می‌شود تا از تداخل نسخه‌ها (Dependency Conflicts) جلوگیری شود.
- نسخه پلاگین کاتلین و Android Gradle Plugin (AGP) کاملاً هماهنگ هستند.
- ابزارهای غیرضروری و کتابخانه‌های سنگین بدون استفاده کامنت یا حذف شده‌اند تا حجم نهایی فایل APK در کمترین حالت ممکن باقی بماند.
