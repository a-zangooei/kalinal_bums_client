# ⚙️ معماری خط لوله‌های GitHub Actions (CI/CD Architecture)

مخزن کالینان مجهز به یک سیستم خودکارسازی بیلد، تست و توزیع صنعتی با اصل حداقل دسترسی (Least Privilege) و اجرای بهینه ابری است.

---

## ۱. پایپ‌لاین خودکار واحد (`.github/workflows/ci.yml`)

برای هر کامیت، پوش (Push) یا پول‌ریکوئست، **تنها یک وورک‌فلو واحد** با نام پویا اجرا می‌شود:
* **عنوان پویا در گیت‌هاب:** `Auto Workflow commit {commit_id} (#{run_number})`

این وورک‌فلو دارای **۳ جاب تفکیک‌شده** با ساختار زیر است:

```
               ┌────────────────────────────────────────────────────────┐
               │    Auto Workflow commit {commit_id} (#{run_number})    │
               └───────────┬────────────────────────────────┬───────────┘
                           │                                │
                           ▼                                ▼
              ┌─────────────────────────┐      ┌─────────────────────────┐
              │   Job 1: 📦 Build APK   │      │ 📚 Job 3: Sync to Wiki  │
              └────────────┬────────────┘      └─────────────────────────┘
                           │
                           ▼ (پشت سر بیلد)
              ┌─────────────────────────┐
              │   Job 2: 🧪 Unit Tests  │
              └─────────────────────────┘
```

### شرح وظایف هر جاب:
1. **جاب ۱: کامپایل فایل نصبی دیباگ (`build`):**
   - کامپایل `assembleDebug` با کلید موقت ایزوله‌شده.
   - اعتبارسنجی تولید فیزیکی فایل `.apk`.
   - نام‌گذاری معنایی بر مبنای برنچ و هش کامیت: `Kalinal-v1.0-debug-{branch}-{short_sha}.apk`.
   - محاسبه اثرانگشت SHA-256 و آپلود فایل نصبی در بخش **Artifacts** (با ماندگاری ۱۴ روز).
2. **جاب ۲: آزمون‌های کیفیت و تست‌های واحد (`test`):**
   - به صورت متوالی پس از اتمام کامپایل اجرا می‌شود (`needs: [build]`).
   - اجرای تسک `testDebugUnitTest` (شامل تست‌های واحد RSA، پارسر دلتا و شبیه‌سازی سرور با MockWebServer).
   - تحلیل نتایج با اسکریپت پایتون و تولید جدول آماری در **Step Summary** (شامل درصد موفقیت، مدت زمان و وضعیت هر سوئیت).
   - آپلود فایل‌های گزارش HTML/XML با شرط `if: always()`.
3. **جاب ۳: همگام‌سازی خودکار مستندات با ویکی گیت‌هاب (`wiki-sync`):**
   - به صورت موازی و مستقل از بیلد اجرا می‌شود.
   - کلیه مستندات مسیر `/docs` را به مخزن ویکی گیت‌هاب (`.wiki.git`) منتقل کرده و `docs/README.md` را به عنوان صفحه اصلی `Home.md` تنظیم می‌کند.
   - در صورت عدم فعال‌سازی اولیه ویکی توسط کاربر، بدون قرمز کردن وورک‌فلو راهنمای شفاف درج می‌کند.

## ۲. پایپ‌لاین توزیع و انتشار رسمی (`.github/workflows/release.yml`)

پایپ‌لاین انتشار ریلیز رسمی **صرفاً به دو روش کنترل‌شده و ایمن** فعال می‌شود:
1. پوش کردن تگ نسخه با پیشوند استاندارد `v` (مانند `git push origin v1.0.1`).
2. اجرای دستی از طریق منوی `Actions` -> `Official Release & Signed Distribution` با زدن دکمه `Run workflow`.

### ویژگی‌های کلیدی فرآیند انتشار رسمی:
1. **اجرای الزامی تست‌های واحد (`verify`):** تست‌ها به هیچ عنوان قابل دور زدن نیستند؛ انتشار نسخه معیوب در صورت شکست حتی یک تست مسدود می‌شود.
2. **اعتبارسنجی سکرت‌ها و الیاس پویا:** کلیدهای `RELEASE_KEYSTORE_BASE64`، `RELEASE_STORE_PASSWORD`، `RELEASE_KEY_PASSWORD` و `RELEASE_KEY_ALIAS` از سکرت‌های مخزن خوانده شده و هیچ مقداری هاردکد نیست.
3. **کامپایل دوگانه فایل‌های خروجی:**
   - فایل مستقل و بدون زیپ برای نصب مستقیم: `Kalinal-vX.X-release.apk`
   - بسته استاندارد فروشگاه‌های نرم‌افزاری: `Kalinal-vX.X-AppBundle.aab`
4. **تأیید گواهی با `apksigner`:** استخراج اثرانگشت SHA-256 گواهی امضا و ثبت در گزارش.
5. **امحای امن کلید موقت (`shred -u`):** حذف غیرقابل بازیابی فایل کلید از رانر بلافاصله پس از اتمام امضا.
6. **پیوست خودکار به Release و آپدیت درون‌برنامه‌ای:**
   - متن توضیحات رسمی شامل بخش اختصاصی **`### 📝 تغییرات این نسخه`** در صفحه ریلیز درج می‌شود.
   - کاربر می‌تواند این بخش را در سایت گیت‌هاب ویرایش کند تا مستقیماً در کادر آپدیت درون‌برنامه‌ای اپلیکیشن برای دانشجویان نمایش داده شود.
