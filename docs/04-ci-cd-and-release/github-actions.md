# ⚙️ معماری خط لوله‌های GitHub Actions (CI/CD Architecture)

مخزن کالینان مجهز به یک سیستم خودکارسازی بیلد و تست صنعتی با تفکیک وظایف و اصل حداقل دسترسی (Least Privilege) است. این مستند به ساختار و رفتار خط لوله‌ها می‌پردازد.

---

## ۱. پایپ‌لاین آزمون و کامپایل خودکار (`.github/workflows/ci.yml`)

این پایپ‌لاین با هر پوش (Push) یا پول‌ریکوئست (Pull Request) به شاخه‌ها اجرا می‌شود و شامل **دو جاب کاملاً مستقل و موازی** است:

```
[ رویداد Git Push / Pull Request ]
               │
       ┌───────┴───────┐
       ▼               ▼
 ┌───────────┐   ┌───────────┐
 │ Job: Test │   │Job: Build │
 └───────────┘   └───────────┘
```

### ویژگی‌های کلیدی جاب‌های مستقل:
1. **عدم وابستگی (`needs` وجود ندارد):**
   - شکست در جاب `test` مانع اجرای جاب `build` نمی‌شود؛ و بالعکس.
   - برنامه‌نویس بلافاصله پس از کامیت می‌بیند که آیا مشکل از تست‌ها بوده، از کامپایل بوده، یا هر دو (`Test: PASS/FAIL` و `Build: PASS/FAIL`).
2. **جاب `test` (Automated Quality & Unit Tests):**
   - اجرای تسک `testDebugUnitTest`.
   - اسکریپت پایتون تعبیه‌شده برای پارس فایل‌های XML گزارش تست و تولید یک جدول کامل در Step Summary گیت‌هاب (شامل تعداد تست‌ها، درصد موفقیت، زمان اجرا و وضعیت تک‌تک کلاس‌ها).
   - آپلود گزارش‌های آزمون حتی در صورت بروز خطا با شرط `if: always()`.
3. **جاب `build` (Assemble Debug APK):**
   - محاسبه پویای `versionCode` بر مبنای `git rev-list --count HEAD`.
   - کامپایل `assembleDebug`.
   - تولید نام معنایی برای آرتیفکت خروجی:  
     `Kalinal-v1.0-debug-{branch}-{short_sha}.apk`
   - محاسبه هش اعتبارسنجی SHA-256 و آپلود فایل APK در بخش Artifacts با طول عمر نگهداری ۵ روز (جهت حفظ سهمیه سرور).

---

## ۲. پایپ‌لاین توزیع و انتشار رسمی (`.github/workflows/release.yml`)

پایپ‌لاین انتشار ریلیز رسمی **تنها به صورت دوگانه و کنترل‌شده** فعال می‌شود:
1. پوش کردن تگ نسخه با فرمت `v*` (مثلاً `git push origin v1.0.0`).
2. اجرای دستی از طریق منوی `Actions` -> `Run workflow` در گیت‌هاب.

### مراحل فرآیند انتشار رسمی:
1. **جاب `verify`:** اجرای اجباری کلیه تست‌های واحد قبل از آغاز کامپایل ریلیز (حذف کامل امکان دور زدن تست‌ها).
2. **بررسی امنیتی سکرت‌ها:** اطمینان از وجود کلیدهای امضای دائمی در Secrets گیت‌هاب.
3. **کامپایل فایل‌های دوگانه ریلیز:**
   - تولید فایل مستقیم `.apk` قابل نصب با یک لمس (`Kalinal-vX.X-release.apk`).
   - تولید بسته استاندارد فروشگاه‌های نرم‌افزاری `.aab` (`Kalinal-vX.X-AppBundle.aab`).
4. **راستی‌آزمایی امضا با `apksigner`:** استخراج و ثبت اثرانگشت SHA-256 کلید رسمی و تایید سلامت فایل‌ها.
5. **امحای امن کلید:** حذف غیرقابل بازیابی فایل موقت کلید در رانر لینوکس با ابزار `shred -u`.
6. **انتشار مستقیم در Releases گیت‌هاب:** بارگذاری خودکار فایل‌های مستقیم نصبی، متادیتا و فایل `SHA256SUMS.txt`.
